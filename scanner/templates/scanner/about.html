About Sentinel

Sentinel checks your dependency files against public vulnerability advisories and collects the latest security news in one place. Signed-in operators can also run security tools against their own Git repositories, and every action there is written to a tamper-evident audit log.

Site map

Every page and endpoint, and who can open it.

  • Public anyone
  • Role signed in with GitHub and given a role
  • Staff admins and permitted staff only
  • API called by a page, not opened directly
  • / Home PublicWhat Sentinel does, then the latest security news and official reports
    • /scan/ Scan PublicGET shows the upload form; POST runs the scan and redirects to the result
      • /parse/ Detected packages APIPOST, returns JSON: the packages found before you scan
    • /results/ Results PublicYour recent scans, kept only for this browser session
      • /results/<id>/ Scan result PublicFindings by package, the sources behind them, severity and the upgrades that fix them
    • /about/ About PublicThis page
    • /server/ Security runs RoleTargets and recent runs (operators, auditors, admins)
      • /server/targets/add/ Add target RolePOST: register a Git repository to scan (operators, admins)
      • /server/start/ Start run RolePOST: run the security pipeline against a target (operators, admins)
      • /server/runs/<id>/ Run detail RoleEach step, its captured output and the findings
        • /server/runs/<id>/status/ Run status APIJSON polled by the run page until the run finishes

Under the hood

One Django project with four apps. Each app owns its own pages and data.

  • configSettings, root URLs and the WSGI entry point
    • scanner /Dependency scanner, news and the public site
      • parsersReads requirements.txt, pyproject.toml, package.json and lockfiles
      • scan · sources · versionsAsks all six sources at once, merges duplicates, and matches exact versions and ranges
      • triageSorts findings into confirmed, possible and already fixed; exploited and malicious first
      • news · headlinesRSS feeds, CVE matching, the newsroom and the ticker
      • http_client · storeOutbound requests, and the cache of public lookups (never your uploads)
      • historySession-only result history
      • middlewareRequest tracing, security headers, rate limiting and no-store caching
      • ScanLog modelTime, IP and package list per scan, deleted after {{ retention_days }} days
    • pipeline /server/Security runs on registered Git targets
      • gitsafeValidates repository URLs and refs before anything is cloned
      • runner · jobs · adaptersRuns each tool step in the background and parses its output
      • bugchecks · osvlocalBuilt-in bug checks and the offline OSV database
      • accessPermission checks for every pipeline page
      • Target · Run · Step · Finding models
    • accounts /auth/GitHub sign-in and roles
      • githubThe OAuth sign-in flow
      • roles · identityMaps listed GitHub logins to operator, auditor or admin; anyone else is refused
      • middlewareSigns out anyone removed from the list on their very next request
    • auditTamper-evident record of what happened
      • logAppends hash-chained events and stores evidence by its SHA-256
      • AuditEvent · EvidenceArtifact models
      • verify_audit commandRe-checks the whole chain from the command line
