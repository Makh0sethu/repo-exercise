About Sentinel

Sentinel checks your dependency files against public vulnerability advisories and collects the latest security news in one place.{% if not public_only %} Signed-in operators can also run security tools against their own Git repositories, and every action there is written to a tamper-evident audit log.{% endif %}

How a scan travels

From your browser to the sources and back, and what is kept along the way.

Text version
  1. YouUpload or paste a dependency file
  2. CloudflareEncrypts the connection and absorbs attacks
  3. nginxRate limits scans; only public pages pass
  4. SentinelReads the file in memory, asks the sources, ranks the findings
  5. 6 public sourcesOSV.dev · CISA KEV · NVD · CVE.org · RetireJS · news feeds
  • Your fileNever stored: read in memory, then thrown away
  • Your resultsOnly in your browser session, gone when you close it
  • Scan logTime, IP address and package list, deleted after {{ retention_days }} days
  • Public cacheAdvisory records and news feeds, so repeat scans are fast

Under the hood

{% if public_only %}The parts of Sentinel that run this site.{% else %}One Django project with four apps. Each app owns its own pages and data.{% endif %}

{% if public_only %} {% else %} {% endif %}
Text version

configSettings, root URLs and the WSGI entry point

scanner/Dependency scanner, news and the public site

  • parsersReads requirements.txt, pyproject.toml, package.json and lockfiles
  • scan sources versionsAsks all six sources at once, merges duplicates, matches versions and ranges
  • triageConfirmed, possible or already fixed; exploited and malicious first
  • news headlinesRSS feeds, CVE matching, the newsroom and the ticker
  • http_client storeOutbound requests, and the cache of public lookups (never your uploads)
  • historySession-only result history
  • middlewareRequest tracing, security headers, rate limiting and no-store caching
  • ScanLogTime, IP and package list per scan, deleted after {{ retention_days }} days
{% if not public_only %}

pipeline/server/Security runs on registered Git targets

  • gitsafeValidates repository URLs and refs before anything is cloned
  • runner jobs adaptersRuns each tool step in the background and parses its output
  • bugchecks osvlocalBuilt-in bug checks and the offline OSV database
  • accessPermission checks for every pipeline page
  • Target Run Step FindingModels

accounts/auth/GitHub sign-in and roles

  • githubThe OAuth sign-in flow
  • roles identityMaps listed GitHub logins to operator, auditor or admin; anyone else is refused
  • middlewareSigns out anyone removed from the list on their very next request

auditTamper-evident record of what happened

  • logAppends hash-chained events and stores evidence by its SHA-256
  • AuditEvent EvidenceArtifactModels
  • verify_auditRe-checks the whole chain from the command line
